cln-tui: a terminal UI for Core Lightning

2026-08-12

introduction

cln-tui is a terminal interface for Core Lightning. it talks straight to lightningd over its RPC socket, no REST plugin, no gRPC plugin, no extra process to keep alive alongside the node. just a Go binary and a Unix socket.

i wanted something i could ssh into a node and immediately see what's going on: peers, channels, invoices, payments, without reaching for lightning-cli and piping everything through jq.

how it's built

it's written in Go using gocui for the terminal UI, with a JSON-RPC client that talks to lightning-rpc directly and typed wrappers around the CLN RPC methods it needs. no separate daemon, no lnd-style REST layer, it's just another client of the same socket lightning-cli uses.

the interface is split into eight panels: Wallet, Peers, Channels, Invoices, Forwards, Payments, Offers, and the network graph. the layout is accordion-style, three panels expanded at once (whichever is focused plus its neighbors), with jump keys 1-8 for going straight to any of them. Tab cycles focus, j/k or the arrow keys move the selection, / fuzzy-searches, r refreshes, and ? pulls up help scoped to whatever panel you're in.

panel-specific actions follow what you'd expect from each screen: o opens a channel, x closes one, n creates a new invoice or offer, p/x handle payments, and y copies whatever's selected to the clipboard. destructive actions like closing a channel or withdrawing funds ask for confirmation first.

staying responsive on a real node

the annoying part of any CLN UI is that some calls are just slow, listnodes against the gossip graph on a well-connected node can take a while and there's no reason the rest of the UI should freeze while it runs. cln-tui fetches gossip data in the background and lets you keep working in the other panels while it loads.

first connection shows a progress bar while the initial dataset is pulled; later launches reuse cached data so you're not staring at a blank screen every time you ssh in. Invoices, Payments, and Forwards only ever render and cache their most recent 300 entries, newest first, which keeps things fast on nodes that have been routing for a long time and have thousands of records to page through.

getting it running

it's a straight go build -o cln-tui ., then run ./cln-tui. by default it looks for the RPC socket at ~/.lightning/bitcoin/lightning-rpc, but the path and the auto-refresh interval are both overridable via flags or environment variables, useful if your node lives in a container or a non-default data dir.

for development there's a Docker-based regtest environment in the repo, so changes can be tested against a live bitcoind and lightningd instead of just against mocks, plus CI workflows for tests and cross-platform release builds for Linux, macOS, and Windows.
